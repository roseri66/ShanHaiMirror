## 第一次开工：事件层 + 画像层

### 做了什么

- **事件总线类型化**（`794e73e`）：原骨架 `Broadcast(Tag, Actor*)` 传不了数据且零调用点；重做为带负载的 `FSHMGameplayEvent`（EventTag/SourceTag/ContextTag/Magnitude/bSuccess），并在战斗代码接线 9 个广播点（攻击/切武器/闪避/受击/低血/死亡/伤害/击杀，含武器→击杀归因）。
- **原生 GameplayTag**：以 `UE_DEFINE_GAMEPLAY_TAG` 取代 `RequestGameplayTag` 字符串查找，标签拼错从"运行时静默统计不到"变为"编译不过"；ini 中已 native 化的标签删除，保持单一来源。
- **行为记录器** `USHMBehaviorRecorder`：订阅总线累积层快照。边界纪律：只计数不打分；不读世界时间（耗时由事件携带）——因此可脱离引擎单测。
- **画像分析器** `FSHMProfileAnalyzer`（`8e71c8c`）：纯静态函数（无状态/无 UObject/无随机数），五维 0-100 画像 + 主导原型 + 连续同打法置信度。
- **输入修复**（`c90a4b1`）：Standalone 下视口无键盘焦点，玩家开局不能动（踩坑 #12）。

### 关键设计判断

1. **快照存原始计数，不存比率。** 比率丢样本量：闪避 2 中 1 与 40 中 20 都是 50%，但统计意义天差地别。除法留给分析器。
2. **"没数据"与"表现差"必须给不同的分。** 比率型维度（效率/切换）无分母时返回中性 50；计数型维度（生存压力）无事件返回 0——零事件本身就是有效观测。否则导演会把没开打的玩家当成在挣扎的玩家照顾。
3. **资源盈余恒中性。** 当前范围无道具/弹药系统（D-09 砍了 Pick3），字段恒零；照字段打分会稳定产出"资源枯竭"的假信号。没有数据源时诚实地不打分，并用测试锁死该决定。**故当前画像实际是四维 + 一个占位。**

## 第二次开工：决策层

### 做了什么

- **Intent/Decision 类型分离**（`c21ad4c`，DECISIONS D-15 落地）：`FDirectorIntent`（Provider 输出，仅标签+等级）与 `FDirectorDecision`（玩法层输入，带数值）分离。Provider（含未来 LLM）**编译期构造不出带数值的决策**——"LLM 不接触数值"由类型系统强制，不靠纪律。
- **规则表** `Data/RuleTable.csv`：纯文本入库可 diff；`FSHMRuleResolver` 查表出数值，是全链路数值唯一产生点。
- **四道护栏** `FSHMDecisionValidator`：Schema（权重和/白名单/等级合法）· Budget（Σcost≤预算）· Conflict（互斥规则对）· Fairness（同规则不连续 3 层 + 低置信度禁重度）。纯函数（Cost/冲突信息建上下文时拷入），每道各有拒绝+通过路径测试。护栏是为 W4 不可信的 LLM 输出预建的安全网。
- **本地 Provider** `FSHMLocalProvider`：确定性规则表决策，降级终点——单独即完整导演。远程画像→Tank/Rush 反制，近战画像→Shooter 消耗，高压→恢复期全杂兵零规则，低置信度→最多 1 条轻度。
- **DirectorCore 编排** + `SHM.DumpDecision` 控制台命令：手喂画像跑完整链路打印决策。
- **公平性双保险**：建上下文时预过滤已连用满 2 层的规则（Provider 选不到），Validator 再校验一道——护栏不赌上游行为。

### 期间修复（全部由人工验证发现）

| 问题 | 提交 | 教训（踩坑号）|
|---|---|---|
| CSV 放 `Content/` 弹自动导入，误导入即双数据源 | `cbbf723` | #13：代码直读的数据放 Content 之外 |
| F0 台词/配比仍输出"定向反制"，违背「首层只观察」 | `a6d432f` | 设计不变量不能依赖"首层画像恰好为空"，须代码强制 |
| DumpDecision 静默提前返回，零输出无法定位 | `a6d432f` | #15：失败必须出声 |
| `FInputModeGameOnly` 默认吞捕获点击，攻击/闪避间歇失灵 | 本批 | #14：修全局输入的验收单不能只覆盖出问题的路径 |

### 计划偏离（已同步进文档）

- **Recorder/DirectorCore 用 `UGameInstanceSubsystem`**，非 DECISIONS 原定的 WorldSubsystem——层跨多房间的 Level Streaming 会让 World 级生命周期丢掉决策历史（Fairness 护栏与决策日志的数据源）。DECISIONS §4.1 已加修正注。
- **「首层只观察」补了显式短路。** 原以为预算=0 可自然实现，实测只挡得住规则，挡不住台词与配比。

## 第三次开工：玩法接线（闭环合龙）

> 分支 `feature/w3-gameplay-wiring` · 这是项目的**生死线**：闭环第一次肉眼可见，
> 否则前两次全是空转。

### 做了什么

- **武器切换 + 通用投射物**：弓与 Shooter 敌人共用 `ASHMProjectile`；攻击按 `AttackPattern` 分发。默认主剑副弓——弓是**画像分化的输入源**，没有它 AI 永远只看到一种打法。
- **敌人四原型**：数据驱动（`Data/EnemyTable.csv` 含数值/威胁值/识别色），代码生成变体 = 同一 C++ 类 + `InitFromRow` 运行时染色，**零蓝图**。Shooter 保距射击，其余原型差异在数值。
- **遭遇系统消费权重**：`FSHMEncounterMath` 纯函数抽样（排序建桶 + 威胁预算，同种子可复现）+ `USHMEncounterManager` 刷怪与清房判定。**导演的权重第一次有人消费。**
- **层循环合龙**：房间×3 → 真实耗时进画像 → Analyzer → DirectorCore → 下层应用。战斗效率维度从此拿到真数据，不再是中性 50。
- **规则作用面**：Melee/RangedDamage 倍率乘进伤害、Cooldown 乘进闪避冷却。

### 关键设计判断

1. **决策层不引入随机。** 遭遇抽样用固定种子的 `FRandomStream`，同输入同输出可测；"重复游玩的变化"由原型池内抽具体怪实现——分工在 TDD §2.5 就定好了。
2. **不新建蓝图。** 四原型靠 CSV + 运行时染色，加一种怪 = 加一行。前两次开工的经验是**编辑器乒乓是最大的时间黑洞**，能不进编辑器就不进。

### 期间修复（两个都由人工验证发现）

| 问题 | 教训（踩坑号） |
|---|---|
| 「空格切不了弓」——功能一直正常，只是剑弓都没模型没图标，切了看不出来 | #16：**没有视觉表现的功能必须有临时反馈，否则它在测试者眼里等于不存在** |
| 刷怪不验证落点 → 怪刷到平台外坠落 → 永不死亡 → 房间永不结算，整局卡死 | #17：放置 Actor 必须验证落点合法；流程依赖的对象要有坠出世界的兜底清理 |

> 这两个表面完全不同，根子是同一类：**缺的不是功能本身，而是让功能可见/可验证的那一层**——一个没长嘴，一个没长眼。

## 第四次开工：LLM 层（可拔插增强）

> 分支 `feature/w4-llm-layer` · 核心不是"接通 LLM"，是**"接不通时优雅降级"**。
> 架构（`ISHMAIProvider` + 四道护栏 + 本地 Provider）在第二次开工就为这一刻铺好了。

### 做了什么

- **三 Provider 齐备**：`Local`（降级终点，单独即完整导演）· `Llm`（OpenAI 兼容，异步）· `Replay`（确定性回放，脚本即决策日志子集）。
- **三级降级**：①Provider 失败 → ②护栏拒绝 → ③本地也异常则安全兜底。每级留日志，**回调必定被调用一次**，调用方不必处理"没回调"。本地产出同样过护栏，不给任何 Provider 免检特权。
- **`FSHMJsonIntent`**：LLM 与回放共用的解析，"不信任 LLM 输出"的第一道关卡。畸形/截断/模型拒答安全失败；**数值字段一律丢弃**；幻觉标签照常解析交护栏拒绝（解析器管结构，护栏管合法性）。
- **【P2】`FDirectorTrace`**：ProviderId / 是否降级 / 降级原因 / 耗时 / 拦截数。
- **【P3】决策日志**：每层含 `profile/context/rawIntent/validation/decision/trace`，顶层带 `schemaVersion`，一局结束自动导出 UTF-8 JSON。
- **【P1】护栏枚举分道**：违规带 `ESHMGuardrail`，可做"Fairness 拦了 N 次"这类分道统计。

### 实测记录（DeepSeek `deepseek-chat`，三次真实调用走通三条路径）

| # | 耗时 | 结果 |
|---|---|---|
| ① | 3765ms | LLM 同时选中互斥规则（弹药↓ + 远程伤害↓，对远程玩家无解）→ **Conflict 护栏拒绝并降级** |
| ② | 5004ms | 超时 → 降级本地 |
| ③ | 4146ms | 直采通过，0 拦截，台词「箭矢不够用的时候，你还能保持从容吗？」 |

> **第 ① 条是本项目最值钱的一条证据**：护栏不是 README 里的自我宣称，是真的拦住过 LLM 的一次危险决策。

### 实测倒逼出的四处修正（都不是拍脑袋定的）

| 发现 | 修正 |
|---|---|
| prompt 漏注入规则互斥信息，等于让 LLM 盲选 | 候选集必须给全，才叫"只给安全选项" |
| 超时 5s 太乐观（DeepSeek 实测 3.8–5.0s） | 放宽到 10s，可用 `SHM_LLM_TIMEOUT` 覆盖 |
| 层间过场固定 2.5s，4s 才到的决策等于白调用 | 改为"至少 2.5s，但会等决策到齐"（封顶 12s，必须大于 LLM 超时） |
| 导出的 JSON 是 UTF-16，UE 自己读没事但前端/Python 读不了 | 强制 `ForceUTF8WithoutBOM`，并**按字节**断言（按字符串读会被自动转码掩盖） |

### 计划偏离

- **任务 3、4 合并实施**：把 Provider 改异步却让 DirectorCore 保持同步，会留下"选了 LLM 就静默返回空决策"的陷阱——二者不可分割。
- **`FDirectorTrace` 只放标量摘要**，没按扩展建议把 `RawIntent`/`ValidationResult` 塞进 `FDirectorDecision`：后者是 AI 层与玩法层的唯一接口，塞入内部类型会破坏边界并造成头文件循环。完整的护栏前后对照写进决策日志——那才是它们的归属。
- **接口异步化**已补进 `DECISIONS.md §4.1` 修正 ²。

## 第五次开工：可见性收口（MVP 完成）

> 分支 `feature/w5-visibility` · 前四次做的是**系统正确**，这次做的是**让正确变得可见**。
> 一个看不见的正确系统，在 10 分钟的浏览里等于不存在。

### 做了什么

- **导演报告卡**（`ASHMDirectorHUD`）：层间弹出「我看到的（画像）→ 本层调整（配比+规则）→ 白泽台词 → 决策溯源」。用 `AHUD::DrawHUD` 纯 C++ 绘制而非 UMG——**零编辑器资产**，整块 UI 随代码走 git、随构建验证。
- **AI 导演开/关对照**（`SHM.Director 0/1`）：关闭时固定均衡配比、零规则、白泽沉默。**不是让游戏坏掉，是让它变平庸**——这才是「抽掉 AI 体验就坍塌」的证明方式。
- **镜界时间轴**（`SHM.Timeline`）：整局回放，每层「想改什么（护栏前）→ 护栏拦没拦 → 实改什么（含数值）」。
- **本局统计**（`SHM.Stats`）：护栏分道拦截数、降级率、决策平均耗时——简历数字只报实测。
- **README 收口**：四条速览命令 + 真实决策日志样例入库。

### 关键设计判断

1. **纯 C++ HUD 而非 UMG。** 无美术资源下，报告卡要的是「信息层次清楚、能截图录屏」，不是视觉效果。UMG 要建 WBP、连绑定、配 GameMode，全是手工点击——而第三次开工已经证明**编辑器乒乓是最大的时间黑洞**。
2. **对照组的语义是「变平庸」不是「出错」。** 关掉导演后游戏依然完整可玩，只是退化成普通刷怪。两局对照才有说服力。
3. **样例日志必须是真的。** 拒绝手工编造——这份文件的全部价值就在于它是真实对局导出的（近战打法，F1/F2 由 DeepSeek 直采，台词针对玩家实际打法生成）。

### 实测反馈修复（四轮人工验证，每轮都抓到东西）

| 反馈 | 修正 | 教训 |
|---|---|---|
| 内容画到卡片框外 | 先排行表算精确高度再画底板 | #21：内容行数不固定的面板，尺寸必须由内容算出 |
| 卡还在显示，怪已经打上来了 | 流程等 UI：决策到齐 + 卡片确认，两道门才刷怪 | #21：让流程等展示，而不是给两者各设时长祈祷对得上 |
| 没接 LLM 却显示「决策来源 Llm」 | 角标改显示**实际决策者**（降级时显示「Llm → 已降级本地」） | #20：UI 显示「实际发生了什么」，不是「配置成了什么」 |
| 废 key（`"1"`）让每层白发一次 401 | 401/403 后自我停用，本局不再尝试 | #20：凭据可用性判断不能只看「非空」 |

> 第 3 条尤其值得记：**它和第三次开工的 #16「功能没长嘴」是同一类问题的两面**——
> 那次是有功能没显示，这次是显示了但显示的是错的东西。

### 意外收益

「流程等卡片读完」这个改动顺带**彻底解决了 LLM 延迟问题**：卡片在等玩家读，玩家在读卡，
4~6 秒的往返藏在阅读时间里，完全不可感。这比原计划「用 UI 填补空白」更彻底。

## 第六次开工：Web 决策回放器（MVP 之后的第一条加法）

> 分支 `feature/w6-webreplay` · 设计全文：`C:\Dev\开发计划文档\山海镜-前端回放器-设计.md`
> **这是冻结后的第一条范围扩展**，因此动工前先在 `DECISIONS.md` 追了 D-21 并新开 §7，
> 把"冻结前的减法"与"冻结后的加法"分开记——两者规矩不同，混在一起会让"只做减法"失去意义。

### 为什么要它

README 里"护栏确实在约束 LLM"是全项目最核心的主张，但此前**只有装了 UE 5.5
并跑起工程的人验证得了**。面试官平均停留 10 分钟，不会为此装一个引擎。
决策日志 JSON 早就能导出，可让人读原始 JSON 自己比对 `rawIntent` 与 `decision`——没人会做。
证据存在但传达不出去，等于没有。

### 做了什么

- **M0 数据契约层**：`types/decisionLog.ts` 是 `SHMDecisionLogFormat.h` 的 TS 镜像；
  `parseDecisionLog()` 一次收集全部问题而不是抛第一个就停，能降级就不报错，
  版本不符则明确拒绝解析（字段同名而语义已变，显示错误结论比打不开更糟）。
- **M1 概览 + 时间轴**：统计逻辑抽成纯函数 `computeRunStats()`，组件只管渲染——
  顶部数字会被拿去跟卡片核对，算错比不显示更糟。
- **技术选型克制**：Vue 3 + Vite + TS，**不引 UI 框架、不引状态管理库、不引 ECharts**。
  雷达图手写 SVG（M3）。判据是「专用件的复杂度 vs 需求的复杂度」——
  需求只是一个五边形，为它引 ~300KB 通用图表库不划算。
- **M2 护栏前后对照（卖点）**：三栏布局，左（护栏前）· 中（四道灯带）· 右（护栏后）。

### 期间修复的三件事（全部由人工验证发现）

**① 契约缺陷：C++ 类型名泄漏进跨语言 JSON。** 前端接日志时发现
`violations[].guard` 实际是 `"ESHMGuardrail::Conflict"` 而非契约假设的 `"Conflict"`，
根因是用了为调试设计的 `UEnum::GetValueAsString()`。更根本的缺口是**契约只定死了
字段名、没定死取值域**，于是取值跟着实现细节漂移。已改用 `GetNameStringByValue`，
并在 `.h` 里补上四类枚举字段的合法取值。踩坑 #22。

**② 降级后台词会被换成本地库的，而前端把它当成了 LLM 说的话。**
`Decision.NarrationLine` 取自 `EffectiveIntent`，护栏拒绝时它已是本地重新决策的结果。
改为两句并排、只在确实不同时才显示——**差异本身就是"护栏连表达一起接管"的证据**。
顺带查出**两种降级下 `rawIntent` 含义完全不同**：护栏拒绝（降级②）时它是被拒的原件，
而 Provider 交不出结果（降级①）时 `DirectorCore` 直接拿本地 Intent 走后续流程
（`SHMDirectorCore.cpp:304`），日志里的 `rawIntent` 已经是本地的，没有原件可对照。
前端据此加了 `degradeKind()` 区分二者——这个坑要是留到 M2，
护栏对照那一屏会在降级①的层上显示一份假的"LLM 意图"。

**③ 演示数据形状失真（本次最值得记的一条）。** 为演示四道护栏，用回放脚本构造了
一份四层日志，三道各拦一次。用户一句「实际跑起来不可能有四层，这个有造假嫌疑」
点破：`FloorManager::TotalFloors = 3`，第 4 层游戏里到不了。
**构造输入没问题（测试替身，输出仍是真代码算的），构造出产品产生不了的状态有问题。**
翻 `Saved/DecisionLogs/` 后发现用户实打的那一局已经拿到 2 次真实拦截，
且画像演进（置信度 0.50→0.70）、等级递进（Stable→Pressure→Counter）俱全——
比构造的夹具强得多，只是没人注意到。踩坑 #23。

### 意外收益：三份样例成了三个典型

处理完形状失真问题后，样例反而比原计划更完整：

| 样例 | 性质 | 证明什么 |
|---|---|---|
| `DecisionLog_Sample.json` | 真实对局 · LLM 直采 | 顺利路径跑得通，LLM 确实承担"选择与表达" |
| `DecisionLog_Guardrail_Run.json` | 真实对局 · 拦 2 次 | 护栏在真实对局中确实拦截并降级，游戏不中断 |
| `DecisionLog_Guardrail_Ideal.json` | 控制台夹具 · 拦 3 次 | 三道护栏结构上都拦得住（理想情况，已标注限制） |

三份都是引擎真实跑出来的，没有一份是手写 JSON。**同时也说明这套链路经过了多轮验证。**

### 三条经验值得写下来

**① 机器测试与人工验证抓的是两类完全不重叠的问题。** 30 个单测没抓到过一个本报告"期间修复"里的问题——它们全部来自真人开编辑器：自动导入弹窗、F0 台词穿帮、鼠标吞点击、Live Coding 命令失效。原因是这类问题都长在**编辑器交互进程**和**焦点/捕获状态切换**里，headless 测试的世界里不存在。结论不是"测试没用"（护栏/画像的边界正确性只有测试能保证），而是**两道工序缺一不可，且人工验收要有明确的清单**（Alt+Tab 往返后的输入、弹窗、台词与行为的一致性）。

**② 修复引入回归的模式出现了两次，值得警惕。** #12 的修复引入 #14（修键盘焦点，吞了鼠标点击）；"预算=0 实现观察层"的巧思漏掉了台词与配比。共同模式：**改全局状态时只验证了当初出问题的那条路径**。对策已写进踩坑规则：输入模式类修改的验收至少覆盖开局键盘/开局鼠标/焦点往返后的键盘鼠标；设计不变量必须由代码强制而非数据巧合。

**③ 演示材料需要和产品代码同等的诚信标准（第六次开工新增）。** 三处失误都出在
"数据/呈现"而非功能：C++ 类型名泄漏进契约、把本地台词当成 LLM 的话展示、
构造出游戏产生不了的四层日志。共同模式是**只验证了"这条数据是不是真跑出来的"，
没验证"它呈现出来的意思对不对"**。前者靠测试，后者只有人能看出来——
用户三次审阅三次点破，机器测试一次都没抓到。作品集项目里，
**被怀疑造假的代价远高于少演示一个功能**，宁可少证明一道护栏，
不可让人对整份数据起疑。

## 代码审查（2026-07-29，clear 前的完整过一遍）

对 UE 侧 8356 行 + 前端约 3600 行做了一次系统性审查，按"项目宣称了什么"排优先级
（四个不变量都落在 Director 层，从那里开始）。**发现 4 项，全部已修。**

### ① [高] LLM 异步回调持有裸指针 —— use-after-free

`SHMDirectorCore.cpp` 与 `SHMLlmProvider.cpp` 的异步回调都裸捕获 `this`。
LLM 是 4–10 秒的 HTTP 往返，**这期间玩家停掉 PIE**，GameInstance 连同子系统、
连同 Provider 一起析构，而请求仍在飞行 —— 响应到达时会写进已释放的内存。
窗口每层一次，且正好落在层间过场，实际很容易撞上。

判断它是疏漏而非取舍的依据：`SHMFloorManager` 里早就用的是 `CreateWeakLambda`。

修：DirectorCore 侧改用 `CreateWeakLambda(this, ...)`；`FSHMLlmProvider` 不是 UObject，
用不了弱 lambda，改为持有一个 `TSharedPtr<uint8>` 存活令牌，回调里 pin 不住就直接返回。

### ② [中] 三级降级零自动化测试 —— 补了 4 个

"第 ④ 步可以整体失败"是四个不变量之一，也是"断网/无 key 完整可玩"的全部依据，
**此前只靠人工验收**，而人工覆盖不到"Provider 交出畸形数据""连本地兜底都被拒"这类路径。

新增 `Tests/SHMDegradationTest.cpp`：降级①（Provider 交不出结果）、
降级②（护栏拒绝，且**日志必须留下被拒的原件**）、观察层短路、
以及"回调在任何路径下恰好触发一次"的契约。53 → 57 个测试。

为此在 `USHMDirectorCore` 上开了一个明确命名的测试缝 `SetupForTesting()`：
`Initialize()` 需要 `FSubsystemCollectionBase&`，自动化测试里造不出来。
它只做依赖装配，**不读环境变量**——测试不该受本机配置影响。

判据不只是"没崩"，而是降级后的**语义正确**：有没有标 degraded、原因是否可读、
被拒的原件有没有留下（否则前端那一屏无从渲染）。
**做了变异测试确认这些断言有牙**：注掉护栏拒绝路径里的 `bFinalDegraded = true`，
只有 `GuardrailRejects` 变红、其余三条不受影响 —— 说明断言是精准的而非一破全红。

### ③ [低] 前端首层选择依赖数据巧合

`App.vue` 的 `selected` 初值为 0，等于假设"日志首层一定是 F0"。三份内置样例碰巧都满足，
所以一直没暴露；换个默认样例或首屏载入一份从 F1 起的日志，详情区会**静默空白**。
修：`watch` 加 `immediate: true`。

### ④ [清理] 死声明

`SHMLlmProvider.h` 声明了 `HandleResponse` 但 .cpp 用 lambda 实现，从未定义。已删。

### 审查中确认无问题的部分

- `ProfileAnalyzer` 的"纯函数"宣称成立：零 UObject / 零随机 / 零世界依赖，实测无引擎依赖
- Fairness 护栏与 `BuildContext` 的数组下标都有边界保护（`Num() >= MaxConsecutiveFloors` 前置判断）
- 无未保护的除法；`ZeroAttack_NoDivideByZero` 已覆盖
- `DecideForFloor` 的同步回调按引用捕获是安全的（本地 Provider 在调用内立即回调，且有 `bGot` 兜底）
- 53 个原有测试的覆盖面扎实：四道护栏各有拒绝+通过路径，画像五维含边界
